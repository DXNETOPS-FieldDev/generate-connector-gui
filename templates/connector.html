Overview

    
Generates the JSON payload for creating or updating an AppNeta alarm connector
       via POST /api/v4/connector/alarm (CREATE) or
       PUT /api/v4/connector/alarm (UPDATE).

    
When an API key and NIS server URL are provided, monitoring point names, policy names,
       and group names are resolved to their int64 global IDs via the AppNeta API.
       A read-only API key is sufficient for all resolution.


    
Fields

    

      
FieldRequiredNotes

      
API KeyYesAppNeta API token. Read-only scope is sufficient for CREATE mode. UPDATE mode (GET connector) requires elevated access.

      
NIS Server URLYesMust be HTTPS (e.g. https://app-01.pm.appneta.com).

      
OrgConditionalOrg ID or name substring. Comma-separate multiple values to generate one payload per org (e.g. 4160, 4275, 6324) — all must share the same root hierarchy. Optional for org-admin keys, which automatically generate one payload per org in their hierarchy when left blank.

      
Connector IDNoLeave blank for CREATE (POST). Set to an existing connector's int64 ID for UPDATE (PUT). The API returns this ID after a successful POST.

      
Notify OnNoWhich events trigger the webhook. Default: both Alarm Raised and Alarm Cleared.

    


    
CREATE vs UPDATE

    
CREATE (Connector ID blank): payload submitted to
       POST /api/v4/connector/alarm. The API assigns an id on success.

    
UPDATE (Connector ID set): the existing connector is fetched (GET) and
       merged with the form values. Fields you fill in override the existing connector; empty
       fields preserve existing values. The merged payload is submitted to
       PUT /api/v4/connector/alarm with id in the body.

    
Filters

    
Include and exclude blocks share the same fields. Alarms must match all
       include criteria and none of the exclude criteria to be forwarded.

    
Leaving a filter field empty means "no restriction" for that field (not "nothing passes").


    
Tags

    
Enter one tag spec per line. Three formats are supported:

    
    
      
  • Category:Value — exact pair (e.g. Location:Chicago IL)
    • 
      
  • Category — all values in that category (e.g. Cloud)
    • 
      
  • :Value — all categories with that value (e.g. :Production)
    • 
    

    
Tags are validated against the org's tag catalog. Unrecognized tags are listed as warnings
       in the output and omitted from the payload.


    
Webhook Auth

    

      
TypeBehavior

      
NONENo built-in auth header. Use Custom Headers for platform-specific token auth (e.g. Authorization: Bearer <token> or a proprietary header your collector requires).

      
BASICAppNeta sends Authorization: Basic <base64 user:pass> on each webhook call. Credentials are embedded in the JSON payload.

      
BEARERAppNeta sends Authorization: Bearer <token>. Token is embedded in the JSON payload.

    


    
MP Types

    
Plain strings are matched case-insensitively as substrings of live type names. The alias
       n10 expands to Windows and macOS. Glob patterns
       (*, ?, +, !) are passed through to the
       API as-is.
